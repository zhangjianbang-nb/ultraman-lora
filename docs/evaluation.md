# 评测方法与踩过的坑

这份文档记录"怎么证明模型真的学会了角色"，以及验证过程中发现的两个会让指标失真的陷阱。

## 1. 主指标：DINOv2 最近质心身份识别率

**为什么不用 FID / CLIP score**：这两个指标衡量"像不像图"和"文图配不配"，无法回答用户真正的问题——
"生迪迦，出来的是不是迪迦"。身份识别率直接测这件事。

做法：

1. 用清洗后的真实图（`data/clean/<id>/`）给每个身份算一个 DINOv2 特征质心。
2. 对每个身份用它的名字生成 N 张图，同样提 DINOv2 特征。
3. 每张生成图在 34 个质心里取最近的一个，命中自己身份算对。
4. 准确率 = 命中数 / 总数。

DINOv2 对颜色、轮廓、装甲结构敏感，但对"这是哪一部作品的哪个角色"没有概念，
所以它是一个**纯视觉身份**的裁判，不受提示词措辞影响。

## 2. 陷阱一：描述型 prompt 会让底模也拿高分

第一版训练用的是 `"<英文名>, <外观描述>, tokusatsu suit"` 这种 caption。评测时如果用同样的
完整描述去提问，**未微调的 SDXL 也能拿到 100%**——因为它只要照着"银色紫色装甲、胸口发光晶体"
画一个银紫色装甲人，DINOv2 就会把它判给迪迦。

实测（3 个身份，n=1）：

| prompt 风格 | 底模 | LoRA |
|---|---|---|
| 名字 + 外观描述 | 3/3（相似度 0.82–0.85） | 3/3 |
| **只有名字** | 1/3 | 1/3（第一版） |

结论：**验收必须用"只有名字"的 prompt**，否则测的是"底模会不会照描述画画"，不是"模型认不认得这个名字"。

## 3. 陷阱二：caption 里总有描述，LoRA 就只学会"描述→外观"

第一版 LoRA 在"只有名字"上没有任何提升（1/3 → 1/3）。原因很直接：训练集里每条 caption
都带外观描述，模型学到的映射是"这串描述 → 这张图"，名字只是描述的一部分，单独拿出来
embedding 就变了，映射失效。

修法：**caption dropout**。训练时每条样本以 40% 概率换成纯名字 caption
（`"tiga ultraman, tokusatsu, full body"`），其余 60% 保留完整描述。这样模型同时学到
两条路径：名字能触发角色，描述也能触发角色。推理端的中文归一化默认走"名字 + 通用后缀"，
和短 caption 完全对齐。

## 4. 陷阱三：SDXL VAE 在 fp16 下溢出

`vae.encode(x)` 在 fp16 下出来的 latent **全是 NaN**，loss 立刻变 NaN 且不会报错
（只在日志里显示 `loss nan`）。必须把 VAE 转 fp32 再编码。解码时同理，但 diffusers 的
`decode()` 不会自动转换 latent 的 dtype，直接 `pipe.vae.to(float32)` 会报
`Input type (Half) and bias type (float) should be the same`，需要在 decode 前手动把
latent 转 fp32（`work/lora_util.py: upcast_vae()`）。

## 5. 陷阱四：peft 的键名前缀

`get_peft_model_state_dict()` 存出来的键是 `...lora_A.weight`（不带适配器名），
而新挂载的适配器注册的是 `...lora_A.default.weight`。加载时不做名字映射，
`set_peft_model_state_dict` 会**静默地什么都不载入**（`unexpected=0`、`missing` 里混着
一堆 UNet 本体权重，很容易被误读成"加载成功"）。`work/lora_util.py: load_into()` 里做了
键名替换，并断言所有 `lora_` 键都已命中。

注意：`missing` 里的 1680 个键是 UNet 本体权重（conv_in、time_embedding 等），
本来就该缺——LoRA 文件里只有适配器权重。

## 6. 陷阱五：`cuda` 默认是 GPU0

本机 GPU0 上跑着别人的训练，并且有一个 `gpu_watchdog.sh` 会杀掉占用 GPU0 的用户进程。
脚本里写 `cuda` 而不设 `CUDA_VISIBLE_DEVICES=1`，训练会在 15–35 秒内被 SIGTERM，
日志只留半行进度，`dmesg` 里什么也没有。所有远端脚本都必须带
`CUDA_VISIBLE_DEVICES=1` 启动。

## 7. 原能力回归

LoRA 只挂在 UNet 注意力投影上，底模权重不动，所以"原能力"理论上不会丢。但为了证明
加载 LoRA 之后通用生成没被带偏，另跑一组 8 个与特摄无关的 prompt（猫、跑车、拉面、雪山、
老人肖像、机器人、海滩、寿司），用同一个种子分别跑底模和 LoRA，比 DINOv2 特征相似度。
相似度高说明构图/内容基本没被改动；低于 0.75 就需要降低 LoRA 强度（`--lora-scale`）。

## 8. 陷阱六：这个指标在 34 个相似奥特曼上根本不成立（最重要的一条）

前面几节的 DINOv2 最近质心准确率，**在 34 个身份的全表上不可用**。验证方法很直接：
把每个身份的照片对半切开，一半建质心、另一半当测试集，做"真照片留出验证"
（`work/metric_audit.py`）。结果：

```
真照片留出 top-1：49.8%（271/544）
```

也就是说，**给指标喂真照片，它也只有一半能认对**。逐身份看更刺眼：

| 身份 | 真照片自召回 | 结论 |
|---|---|---|
| 巴尔坦 / 雷德王 / 哥莫拉 / 加坦杰厄 / 哥尔赞 / 赛文 / 艾雷王 / 泰兰特 | 0.75–0.88 | 指标可信 |
| 杰顿 / 美菲拉斯 | 0.69 | 勉强 |
| **迪迦** | **0.44** | 指标不可信 |
| **赛罗** | **0.44** | 指标不可信 |
| 泽塔 / 特利迦 / 梦比优斯 | 0.19 | 指标不可信 |
| **德凯** | **0.00** | 指标不可信 |

根因：DINOv2-base 的全局 [CLS] 特征对"银红配色 + 发光眼 + 胸口计时器 + 头冠"这一族
设计的分辨力不足，34 个候选里同款太多，质心彼此重叠。**候选集越小越准**——同一个
模型在 6 个身份的子集上能到 83%，在 34 个身份上就只剩 12%，这个落差主要是候选集
变大造成的，不是 LoRA 变差了。

所以本项目最终的诚实口径是：

1. **只在指标已验证的 8 个身份上报告数字**（真照片自召回 ≥ 0.70 的那批）；
2. 26 个相似奥特曼**不报准确率**，改用人工视觉验收（用户本人也是这么验收的）；
3. 任何引用 34 身份准确率的地方都必须同时给出 49.8% 这个天花板。

后续要拿到可用的自动指标，得换更强的身份特征（ArcFace 人脸式度量学习、或
SigLIP/DINOv2-large），或者干脆用 VLM 判读"这是不是迪迦"。

## 9. 陷阱七：数据里混着拼图 / 截图 / 杂志扫描

第一版清洗只按"与质心相似度 ≥ 0.55"过滤，抓不到两类脏图，因为**它们和角色本身很像**：

- **双人拼图**：左右两格各放一张同角色图，两张都是该角色，相似度当然高；
- **电视截图 / 杂志扫描**：带黑边、日文字幕、水印、"動画 図鑑"角标。

第一版模型（14000 步、`lora-scale 1.0`）的输出里原样出现了这些东西：双人并排构图、
日文字幕条、杂志水印。像素相关性审计（`work/memorization_audit.py`，64×64 灰度相关）
显示最高只有 0.44、均值 0.25，**不是复制训练图，是学会了这个画风**——数据脏，
模型就照脏的画。

`work/filter_hard.py` 加两道结构性过滤，不靠语义：

- **seam**：相邻列/行梯度在某一条线上贯穿 ≥45% 画面且该线强度是全场中位数的 3 倍
  → 拼图接缝 / 杂志装订线；
- **letterbox**：四边任一条 5.5% 边带的标准差 < 7 → 黑边截图 / 白底扫描页。

1370 张里剔掉 703 张（51%），剩 667 张、每身份 12–21 张，用 `data/manifest2.json`
重训（5000 步、lr 5e-5、caption dropout 0.4）。

## 10. 陷阱八：拿生成图去比对真人剧照质心，域差压倒一切

第 8 节的 8 个"可信身份"子集上，真照片留出 top-1 是 **88.3%**（候选集缩小到 8 个，
质心不再互相覆盖）。但同一个子集上跑 LoRA 生成图：

```
base8     18.8% (6/32)
lora8     18.8% (6/32)     lora 完全没涨
lora8@0.7 12.5% (4/32)
```

**为什么涨不了**：质心来自真人皮套照/剧照，而 LoRA 输出是渲染插画。两种视觉域的
全局特征本来就隔得很远，一张画得很对的迪迦，其 DINOv2 特征可能离"迪迦真人照片质心"
比离"盖亚真人照片质心"还远。域差 > 身份差，指标失效。

于是换了两个**域内自洽**的指标：

### 10.1 生成图互相比对（`work/eval_generated.py`）

每个身份用同一句模板生成 K 张，用生成图自己建质心，留一法测 top-1：

```
base: 0.0% (0/102), chance 2.9%, intra 0.836 / inter 0.806 / gap +0.030
lora: 1.0% (1/102), chance 2.9%, intra 0.793 / inter 0.786 / gap +0.007
```

两个数字都低于随机。原因不是"模型全错"，而是**全局 [CLS] 特征被姿态和背景主导**：
同一句 prompt 换种子，人物姿势、镜头、背景全变，这些变化对特征的贡献远大于"这是哪个
角色"。所以 intra-identity 相似度天然接近 inter-identity。这个指标同样不能用。

### 10.2 名字到底有没有用（`work/name_influence.py`）

不碰 DINOv2，直接量像素：同一身份换种子 → 得到"种子噪声"；不同身份同种子 →
得到"换名字带来的变化"。比值 >1 才说明名字真的在控制画面：

```
ratio = mean_cross_name_diff / mean_cross_seed_diff
```

底模应该 ≈1（它根本不管名字）；能用的 LoRA 应该 >1.5。这是目前唯一在数值上
站得住的"名字是否起作用"的判据——但它只证明"名字有影响"，不证明"影响是对的"，
对不对只能靠看图。

### 10.3 结论：身份准确率只能靠人眼

三个自动指标全部失效，原因各不相同（候选集太大 / 域差 / 姿态背景主导）。这不是
指标调参能解决的，要真正自动判定得换模型：SigLIP、DINOv2-large、或直接用 VLM
判读"这张图是不是迪迦"。本项目最终以**人工看图**为验收口径（用户本人也是这么验收的），
自动指标只用于"原能力回归"这一项（第 7 节，它不涉及身份识别，是可靠的）。

## 11. 交付件的溯源与等价性（实测）

交付的 `ultraman-lora-r32.safetensors`（93,076,552 B）是远端 fp32 权重
`out_c4/lora_step12000.safetensors`（185,974,936 B）经 `work/export_lora.py` 转 fp16 的结果。
两者字节不同是转换的正常结果，所以做了两项实测而不是靠"看起来一样"：

1. **同一文件**：本地交付件与远端导出件的 sha256 完全一致（`da28cf92…`），排除了传输损坏或拿错文件。
2. **数值等价**：同一 prompt（`生迪迦`）、同种子（777）、同 `lora-scale 0.9`、30 步，
   fp32 原权重与 fp16 交付件渲染出的图**平均像素差 0.321/255（0.13%）**，仅由 fp16 舍入在
   30 步扩散中放大所致。验收用的权重与交付的权重实际等价，对照表 `compare_sheet.jpg`
   的结论对交付件同样成立。

### 11.1 交付件能力漂移复测（2026-10-30，c4 fp16）

早前 README 引用的 0.773 / 0.748 来自不同检查点，没有日志留档。交付前用交付件本身重测两档：

| lora-scale | mean drift sim | 最低单张 | 退化图 | 判定 |
|---|---|---|---|---|
| 0.9（交付默认） | **0.775** | 0.445（雪山） | 0 | PASS |
| 1.0 | **0.758** | 0.432（雪山） | 0 | PASS |

逐张最低的是"雪山风景"（0.445/0.432）与"跑车街景"（0.611/0.590）——奥特曼训练数据里
大量"人形主体 + 纯色背景"，把构图先验往"居中单体"拉，风景类受影响最大。猫（0.876）、
拉面（0.875）、老人肖像（0.890）、寿司（0.969）几乎无损。
日志留档：`data/reports/cap_c4_s0.9.log`、`data/reports/cap_c4_s1.0.log`。
